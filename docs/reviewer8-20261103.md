## Changes in this follow-up

The JSON parser previously accepted malformed numeric tokens through partial
strtod conversion and silently truncated fractional integer fields. Optional
state arrays skipped nonnumeric entries, and stoi accepted numeric prefixes in
state-override keys. Those behaviors could change a user's intended experiment
before it reached the material interface.

- Require valid JSON number syntax and a finite representable double.
- Reject fractional or out-of-range integer fields before casting.
- Reject wrong array types and nonnumeric initial-state entries.
- Require integral nonnegative indicator indices, complete decimal override
  keys and equivalentPlasticStrainIndex of -1 or an existing state slot.
- Reject overflow of the total integration duration before simulation.
- Add JSON numeric tests and extend public-runner configuration rejection tests.

These are input-behavior fixes, not new constitutive, correspondence, rotation,
force or time-integration algorithms. Existing valid configurations keep their
numerical interpretation. Inputs formerly truncated or partially ignored now fail
with an error. The scalar initial-state and index arrays remain model-specific.

The reusable `benchmarks/tensile3d/time_step_study.py` runs a temporal sequence
without reusing existing output or overwriting the publication archive. It keeps
the physical setup fixed, records executable/material/source/result hashes and
checks complete finite output. See [the time-step guide](time-step.md).

## New numerical evidence

Three new solves used the existing undamaged coarse JC PD case: a 100 x 20 x 4 mm
domain, 51 x 11 x 3 nodes, h=2 mm, horizon=6 mm, 2 mm end displacement and 0.12 ms
loading duration. The steps were 50, 25 and 12.5 ns, with 2400, 4800 and 9600
increments. All three completed and passed the configured solver diagnostics.
The material file, plugin and all spatial/loading parameters were identical.
Two OpenMP threads were used with the supplied reentrant JC plugin.

| Adjacent PD runs | Stress-history NRMSE | Displacement RMSE divided by 2 mm | Maximum eqps difference |
|---|---:|---:|---:|
| 50 versus 25 ns | 0.209967% | 0.168819% | 0.538483% |
| 25 versus 12.5 ns | 0.091556% | 0.066351% | 0.228338% |

Each comparison uses the finer PD run, 240 identical physical times for stress,
and all final nodal displacement components. First-increment samples that occur
at different times are excluded. Displacement RMSE averages over 3N components.
The reported maximum-eqps point is at reference coordinates (86, 0, -2) mm in
each run; a first-maximum location does not establish that the peak is unique.

The configured elastic continuum wave speed is 6020.183 mm/ms and h/c_p is
0.000332216 ms. The 25 ns input is 0.07525 times this estimate. These are screening
quantities, not the spectrum of the discrete PD system. The new runs support
temporal sensitivity statements for this coarse case; they do not establish an
asymptotic order, general stability limit, spatial convergence or absence of
zero-energy modes. They retain the archived JC thermal convention, so they do
not validate physical adiabatic temperature rise.

Evidence is retained in [validation/reviewer8-20261103](../validation/reviewer8-20261103/).

Full new fields, inputs and logs remain in the ignored

## Numerical work still open

Zero-energy stabilization needs a selected formulation, consistent forces and
energy, parameter justification and recomputed benchmarks. It has not been
added as an undocumented penalty. Physical thermal coupling, full finite-rotation
verification, fracture validation and automatic time-step estimation remain
outside the demonstrated scope. These items must not be marked solved merely
because documentation now states the limitation.
