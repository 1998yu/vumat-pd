# Build and reproduce from a checkout

Requirements: CMake >=3.25, Ninja, C++17 and GNU Fortran compilers, OpenMP.
Python 3 with NumPy/Matplotlib is needed for benchmark analysis. Set compiler
runtimes on PATH on Windows. Run commands from the repository root.

## Minimal verification

```bash
cmake --preset release
cmake --build --preset release --parallel 4
build/release/bin/vumat_pd_run examples/jc_material_point.json
ctest --preset release --output-on-failure
```

Use .exe on Windows when required by the shell. This is a small material-point interface
check, not a spatial-convergence result. The reference tensile configuration is
benchmarks/tensile3d/cases/pd_coarse.json.

## Complete release checks with retained logs

```bash
python -m pip install -r benchmarks/tensile3d/requirements.txt
python tools/verify_release.py
```

For the optional independent Eigen check:
`python tools/verify_release.py --eigen-dir /path/to/eigen-3.4.0`.
Logs and command/exit-code records go to build/verification. No code is committed,
no file is uploaded, and no publication result is silently regenerated by this command:
the numerical tests run; the publication metrics are recomputed from checked archives.

## Fresh publication solves

```bash
python benchmarks/tensile3d/run_cases.py --threads 2 --workers 1 --overwrite
python benchmarks/tensile3d/analyse_and_plot.py --results benchmarks/tensile3d/generated/results
python benchmarks/tensile3d/verify_metrics.py
```

This runs the full matrix, including the FEM reference; it is more expensive.
Use --cases to select a diagnostic subset, but the complete comparison script
requires all reference cases. Test and publication tolerances are distinct.

## Archive integrity

Gzipped CSV data are always checked byte-for-byte after decompression. JSON
metadata are hashed after replacing CRLF by LF; all other bytes, including values
and whitespace, remain significant. The same rule creates and verifies the manifest.
Git attributes request LF JSON files. The JSON normalization also supports existing
Windows working trees without ignoring any numeric metadata change.

Validate an uncommitted revision by overlaying only its reviewed changes onto a
fresh clone, recording their hashes, and starting with an empty build directory.
Call this a fresh-clone candidate test, not proof that the unchanged remote commit
contains the candidate. Windows results do not substitute for a Linux CI run.
